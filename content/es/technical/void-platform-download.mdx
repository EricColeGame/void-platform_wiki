## Qué significa realmente "Void Platform download"

La mayoría de las personas que buscan una descarga de Void Platform esperan un único archivo instalador y un asistente de siguiente-siguiente-finalizar. La realidad es distinta: Void es una plataforma autoalojada que tu equipo despliega en una cuenta de Cloudflare compartida, y el paso de "descarga" en realidad consiste en poner en marcha las herramientas de la plataforma y ejecutar su flujo de configuración. Entender esa distinción desde el principio ahorra horas, porque determina si necesitas una plataforma o no. Si estás publicando una aplicación solo para ti, despliegas directamente en Cloudflare y te saltas la plataforma por completo.

Una plataforma Void es la capa compartida entre tus desarrolladores y Cloudflare. Como administrador, la instalas y la mantienes en funcionamiento. Después, los desarrolladores apuntan la CLI de Void a la URL de la plataforma, inician sesión mediante uno de los métodos de acceso habilitados y despliegan sus aplicaciones en esa cuenta compartida. Cada parte del proceso de descarga de Void Platform existe para que esa transferencia sea fiable y repetible.

Como la plataforma vive en tu cuenta de Cloudflare y no en un portátil, la descarga tiene menos que ver con un archivo y más con la infraestructura. Trabajarás con credenciales de Cloudflare, requisitos de plan y un conjunto documentado de servicios. La siguiente tabla aclara las expectativas.

| Lo que la gente espera de una descarga de Void Platform | Lo que ocurre realmente |
| --- | --- |
| Un único instalador `.exe` o `.dmg` | La plataforma se compila y se despliega en tu propia cuenta de Cloudflare |
| Se ejecuta en tu portátil | Se ejecuta en la nube, compartida por todo el equipo |
| Instantáneo, sin configurar cuenta | Requiere credenciales de Cloudflare, un plan Workers Paid e infraestructura documentada |
| Obligatorio para cada proyecto | Los desarrolladores individuales pueden desplegar directamente en Cloudflare en su lugar |
| Todo incluido de serie | Una instalación principal es intencionadamente ligera; los complementos son aparte |

## Lista de comprobación de requisitos previos y credenciales

Antes de comenzar una descarga de Void Platform, reúne las cuentas y los accesos que necesitarás. En la práctica, la mayoría de las instalaciones fallidas se deben a un permiso ausente o a un plan con recursos insuficientes, no a la plataforma en sí. Revisar esta lista primero convierte una tarde frustrante en una configuración fluida.

| Requisito | Por qué lo necesitas | Notas |
| --- | --- | --- |
| Cuenta de Cloudflare | Aloja la plataforma y cada aplicación desplegada | Compartida por todo el equipo |
| Plan Workers Paid | Necesario para los Sandboxes gestionados | Se aplica a la cuenta de la plataforma |
| Workers for Platforms | Necesario para una plataforma de equipo | Combínalo con la infraestructura documentada |
| Credenciales de la plataforma | Autentican la instalación y el acceso a la API | Se explican en las guías oficiales de instalación |
| Dominio y zona de correo compartidos | Activa la pasarela de correo electrónico | Opcional: el correo permanece desactivado hasta que se configure |
| CLI de Void | Cómo se conectan y despliegan los desarrolladores | Se instala en cada máquina de desarrollador |

Dos de estos merecen especial atención. Primero, el plan Workers Paid debe estar activo en la cuenta de la plataforma, no solo en la cuenta de un desarrollador individual, o los Sandboxes no se ejecutarán. Segundo, las credenciales deben tratarse como secretos de producción desde el primer día, ya que la pasarela de instalación y el proxy se sitúan delante de Workers AI y de las solicitudes a proveedores para cada aplicación de la plataforma.

Si tu organización usa Cloudflare Access para proteger la API, planifica la ruta del webhook con antelación. Las plataformas compiladas desde el código fuente que añaden los servicios opcionales de GitHub necesitan una entrada de webhook aislada para que los webhooks entrantes no sean bloqueados por Access. Readaptarlo después es mucho más doloroso que diseñarlo desde el principio.

## Instalación principal frente a servicios opcionales

Una de las mayores sorpresas tras una descarga de Void Platform es descubrir qué incluye una instalación estándar, y qué deja fuera deliberadamente. El núcleo es ligero por diseño: Sandboxes gestionados más una pasarela de correo electrónico, con el correo habilitado solo una vez que configuras un dominio y una zona de correo compartidos.

| Incluido en una instalación principal | No incluido en una instalación principal |
| --- | --- |
| Sandboxes gestionados | Panel de usuario |
| Pasarela de correo electrónico (tras configurar dominio y zona) | Compilaciones y webhooks de GitHub |
| Acceso compartido para el equipo | Build Containers |
| Historial de despliegues retenido | Dominios de proyecto personalizados |
| Pasarela de instalación y proxy para solicitudes de IA | Integraciones gestionadas de GitHub de cualquier tipo |

Esa división importa cuando planificas un despliegue. Un equipo que espera un panel cuidado desde el primer día se llevará una decepción a menos que alguien lo cree o lo añada. Del mismo modo, los equipos que dependen de compilaciones impulsadas por GitHub necesitan la capa de servicios opcionales, y los equipos que quieren dominios de proyecto de marca deben planificar ese trabajo por separado.

El enfoque práctico es instalar primero el núcleo, verificar que los Sandboxes y los despliegues funcionan, y solo entonces añadir los extras por capas. Cada complemento aumenta la superficie que mantienes, y un servicio opcional averiado es mucho más fácil de diagnosticar cuando el núcleo está en buen estado.

## Cloudflare directo frente a una plataforma autoalojada

Antes de comprometerte con una descarga de Void Platform, confirma que una plataforma es el objetivo correcto. Ambas rutas usan las mismas API de aplicación, así que no quedas atado a ninguna de las dos formas: la diferencia está en el acceso compartido y el historial retenido.

| Característica | Directo a Cloudflare | Plataforma autoalojada principal |
| --- | --- | --- |
| Workers AI y solicitudes a proveedores | Tu cuenta y tu pasarela | Pasarela de instalación y proxy |
| Registros en tiempo de ejecución | Tail en vivo de Cloudflare | Registros de la plataforma retenidos |
| Reversión de aplicación | Versiones del Worker | Despliegues de la plataforma retenidos |
| Sandboxes | Requiere Workers Paid y Docker | Requiere Workers Paid en la cuenta de la plataforma |
| Panel de usuario y compilaciones gestionadas de GitHub | No necesarios | No incluidos en una instalación estándar |

La versión corta: ve directo si estás desplegando una aplicación para ti y quieres el camino más corto a producción. Elige la plataforma si tu equipo necesita un destino de despliegue compartido, registros retenidos y la capacidad de revertir a un despliegue retenido específico en lugar de a una versión bruta del Worker. Fíjate también en la diferencia de los Sandboxes: los despliegues directos necesitan Docker en local, mientras que la plataforma traslada ese requisito a la cuenta de la plataforma.

## Paso a paso: de la descarga de Void Platform al primer despliegue

Con los requisitos previos confirmados, la instalación en sí sigue una secuencia predecible. Trata cada paso como una puerta: no avances hasta que se verifique el anterior.

| Paso | Qué haces | Cómo se ve "terminado" |
| --- | --- | --- |
| 1 | Confirma tu objetivo: Cloudflare directo o plataforma autoalojada | Una decisión clara, documentada para el equipo |
| 2 | Prepara la cuenta de Cloudflare, los planes y las credenciales | Workers Paid activo; Workers for Platforms listo para una configuración de equipo |
| 3 | Compila y despliega la plataforma usando la guía oficial de instalación | Plataforma accesible en su URL |
| 4 | Configura el dominio y la zona de correo compartidos (opcional) | Pasarela de correo activa y enviando |
| 5 | Añade servicios opcionales como compilaciones de GitHub o Build Containers | Cada complemento verificado de forma independiente |
| 6 | Conecta a los desarrolladores mediante la CLI de Void | Un desarrollador inicia sesión y publica una aplicación de prueba |

**Paso 1 y 2: decidir y aprovisionar.** Anota si vas a trabajar en modo directo o autoalojado antes de tocar nada. Después aprovisiona la cuenta de Cloudflare, confirma el plan Workers Paid y configura Workers for Platforms si la plataforma es para un equipo. Guarda las credenciales en un almacén de secretos compartido en lugar de pasarlas por el chat.

**Paso 3 y 4: instalar y configurar el correo.** Sigue la [guía oficial de instalación de la plataforma autoalojada de Void](https://void.cloud/guide/self-hosted-platform) en lugar de improvisar, ya que la infraestructura documentada importa. Una vez que la plataforma sea accesible, configura el dominio y la zona de correo compartidos si quieres la pasarela de correo electrónico: sin ese paso, el correo simplemente permanece desactivado.

**Paso 5 y 6: ampliar e incorporar.** Añade servicios opcionales de uno en uno y prueba después de cada uno. Luego entrega a los desarrolladores la URL de la plataforma y las instrucciones de la CLI, y haz que una persona complete un inicio de sesión y un despliegue completos como prueba de humo antes de anunciar la plataforma al resto del equipo.

| Síntoma | Causa probable | Solución |
| --- | --- | --- |
| Los Sandboxes no arrancan | Workers Paid no está activo en la cuenta de la plataforma | Verifica o mejora el plan en esa cuenta |
| Los desarrolladores no pueden iniciar sesión | Ningún método de acceso habilitado | Habilita un método de acceso compatible en la configuración de la plataforma |
| El correo nunca se envía | Falta el dominio o la zona de correo compartidos | Configura el dominio y la zona, y vuelve a probar |
| Los webhooks de GitHub fallan detrás de Access | Entrada de webhook no aislada | Sigue la configuración de entrada de webhook aislada |
| Funciones de equipo no disponibles | Workers for Platforms no configurado | Completa la infraestructura documentada |

## Preguntas frecuentes

**¿Existe una descarga de Void Platform para Windows o macOS?**
No: no hay instalador de escritorio para consumidores. Una descarga de Void Platform significa compilar y desplegar la plataforma en tu propia cuenta de Cloudflare. Tu máquina local solo necesita la CLI de Void para que los desarrolladores puedan conectarse a la URL de la plataforma y desplegar.

**¿Necesito una descarga de Void Platform si soy un desarrollador individual?**
Normalmente no. Si estás desplegando una aplicación para ti, despliega directamente en Cloudflare y sáltate la plataforma. La plataforma se justifica cuando un equipo necesita un destino de despliegue compartido, registros retenidos e historial de despliegues retenido para las reversiones.

**¿Qué falta en una instalación estándar?**
El panel de usuario, las compilaciones y webhooks de GitHub, los Build Containers y los dominios de proyecto personalizados quedan todos fuera de la instalación principal. Los Sandboxes gestionados y la pasarela de correo electrónico están incluidos, aunque el correo solo funciona una vez configurados un dominio y una zona de correo compartidos.

**¿Qué plan requiere una plataforma de equipo?**
Una plataforma de equipo requiere Workers for Platforms además de la infraestructura documentada, y los Sandboxes gestionados requieren un plan Workers Paid en la cuenta de la plataforma. Las funciones exactas dependen de cómo esté configurada tu instalación, así que revisa las guías oficiales antes de empezar.
